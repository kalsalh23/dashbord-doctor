# نظام إدارة العيادة — Clinic Management System

نظام متكامل لإدارة العيادات الطبية بواجهة عربية (RTL) مبني على React + Supabase، ومهيأ منذ البداية ليكون منتج SaaS متعدد العيادات (عزل كامل لكل عيادة عبر `clinic_id` و RLS).

## المزايا

### واجهة الاستقبال
- لوحة يومية: مواعيد اليوم، قائمة الانتظار، طلبات المتابعة، المحصّل والمستحقات.
- حجز مواعيد فائق السرعة: بحث المريض بالاسم/الهاتف (أو إنشاء جديد) → اختيار اليوم → أزرار أوقات كبيرة قابلة للنقر → تأكيد.
- توليد تلقائي للمواعيد حسب ساعات العمل ومدة الموعد والاستراحات (قابلة للتهيئة من الإعدادات).
- تسجيل وصول المريض مع «دفع الآن» أو «دفع لاحقًا» — الدفع ليس شرطاً لنقل المريض للطبيب.
- قائمة انتظار واضحة + نقل المريض إلى الطبيب.
- تعديل/نقل الموعد، الإلغاء، تسجيل عدم الحضور.
- تذكيرات واتساب برسالة جاهزة قابلة للتعديل + تسجيل وقت الإرسال.
- شاشة مخصصة لطلبات متابعة الطبيب مع الحجز بنقرة.
- مدفوعات: محصّل اليوم، المستحقات اللاحقة، تسديد المتأخرات.

### واجهة الطبيب
- قائمة انتظار نظيفة بلا مشتتات إدارية.
- ملف المريض: المعلومات الطبية الحرجة أولاً (أمراض مزمنة، حساسية، أدوية، عمليات، ملاحظات) ثم آخر زيارة ثم السجل الكامل + المرفقات.
- شاشة كشف مريحة: شكوى، أعراض، فحص، تشخيص، خطة علاج، أدوية، ملاحظات — مع تنبيه حساسية بارز.
- إنهاء الكشف يحفظ الزيارة ويُكمل الموعد تلقائياً، ثم خطوة متابعة بأيام جاهزة (2/4/…/30) وحساب التاريخ المقترح حسب أيام العمل وإرسال الطلب للاستقبال.

### لوحة المدير
- حساب المدير يتنقل بين واجهتي الاستقبال والطبيب من قائمة المستخدم (للعرض والتجربة).
- إعدادات العيادة: الهوية، سعر الكشف والعملة، أيام وساعات العمل، قواعد الاستراحات، نموذج رسالة التذكير.
- عند تعديل ساعات العمل تظهر قائمة المواعيد التي خرجت عن النطاق الجديد دون أي حذف أو نقل تلقائي.

## البنية التقنية
- **Frontend:** React 18 + Vite + Tailwind CSS + react-router-dom + lucide-react
- **Backend:** Supabase (Auth + PostgreSQL + Storage + RLS)
- **قاعدة البيانات:** clinics, profiles, patients, appointments, visits, medical_information, medications, attachments, payments, follow_up_requests, notifications, clinic_settings, doctor_schedules, audit_logs — كلها معزولة بـ `clinic_id` وسياسات RLS صارمة.
- **التخزين:** bucket خاص للمرفقات بمسارات `{clinic}/{patient}/` وسياسات وصول مطابقة.

## التشغيل المحلي
```bash
npm install
cp .env.example .env.local   # ثم عبّئ القيم
npm run dev
```

## متغيرات البيئة
- `VITE_SUPABASE_URL` — رابط مشروع Supabase
- `VITE_SUPABASE_ANON_KEY` — المفتاح العام (anon)

## المستخدمون والأدوار
- `reception` الاستقبال، `doctor` الطبيب، `admin` المدير (يصل لكل شيء).
- إنشاء المستخدمين يتم من لوحة Supabase (Authentication → Add user) ثم ضبط `role` و `clinic_id` في جدول `profiles`.
